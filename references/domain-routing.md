# 전문 스킬 선택 기준

프로젝트에서 결정해야 하는 구조에 따라 필요한 전문 스킬을 고른다. 사용자가 전문 스킬을 직접 지정했고 그 범위만 요청했다면 해당 스킬을 직접 적용할 수 있다.

| 구조를 바꾸는 요구 | 적용 |
| --- | --- |
| Unity의 씬 구성, 판·씬·앱 상태의 수명, 게임 규칙의 소유권, 게임 루프나 갱신 부하 | `unity-game-architecture`를 읽고 첫 플레이의 구조와 검증을 구체화한다. |
| Unity 게임과 별도 백엔드가 함께 저장·매치·인증을 처리 | 범용 절차로 클라이언트와 서버의 쓰기 권한, 데이터 계약, 실패와 재시도 책임을 정한다. Unity 내부의 씬·플레이 구조는 `unity-game-architecture`를 적용한다. |
| 공통 기준으로 충분한 구조 설계 | 범용 절차에서 구조 결정과 검증 조건을 정한다. |
| 다른 기술의 제약이 구조를 바꿈 | 현재 세션에 제공된 전문 스킬 중 해당 구조 결정을 다루는 스킬을 선택한다. |

전문 스킬은 현재 세션의 스킬 목록이 제공한 경로와 읽기 방식으로 찾는다. 파일 기반 설치에서 목록에 보이지 않으면 같은 스킬 루트에 설치된 `unity-game-architecture/SKILL.md`를 확인할 수 있다. 전문 스킬을 사용할 수 없으면 확인된 프로젝트 근거와 공통 기준으로 진행하고, 기술별 확인이 남은 항목을 표시한다.

설계 결과는 한 흐름으로 연결한다. 예를 들어 서버가 세이브 버전을 확정한다면, Unity의 세션은 어떤 상태를 요청으로 보내며 실패 시 누가 어떤 버전부터 다시 시도하는지 같은 설계안에 적는다.
